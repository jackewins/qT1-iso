## Working rules
- Before any run longer than ~10 minutes, and before every parameter sweep, propose it explicitly and wait for the researcher's go-ahead: say what it tests, the exact settings and grid, the expected runtime, and which result would lead to which decision. Short diagnostic runs (single slices, a few minutes) are fine without asking.
- Use `synth/pipeline_utils.py` for everything shared with the other methods (loading, stacking, T1 fit, evaluation). Report bias vs the resolution-limited ideal (`ideal`) as the key number.
- Commit code and executed notebooks (phantom figures only; never phantom data) to `recon-moba` and push. Keep the notebook style of `T1map_3plane_SR_V1.ipynb`: markdown explaining each step and why.
- Be explicit and give reasoning; flag uncertainty rather than guessing.
